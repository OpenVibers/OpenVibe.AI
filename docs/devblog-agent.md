# Devblog writer

`POST /api/v1/runs {task: "blog.devblog.write", input, choice?}` resolves the existing choices task to `content.devblog`. The input carries a site, the week, numbered commit sources, gathered stories, screenshot Media references and a voice card. This is reusable for any configured Blog owner, not an official-blog template. The workflow is authorized through `blog.*`; it does not grant the rest of `content.*` to Blog, and other namespaces cannot invoke it. Blog’s advertised Actor skill routes the owner to the same draft endpoint.

The agent plans, writes and checks every claim against the supplied evidence. Invalid citation indices, unsupported claims, marketing names and block directives in prose trigger one revision followed by a second check. Persistent failures fail the run, with no draft. The model-call budget is five; each call uses the resolved task choice and normal provider accounting/cost ceiling. All step usage is accumulated into the run. Stub prose intentionally fails the evidence gate rather than becoming a publishable post.

The result is a title chosen from five candidates, a plain summary, `publishing.block@1` compatible hero/section/figure/patchnotes blocks, checks and the completed step labels. Screenshots can only come from the gathered references. When a small week supports fewer than four stories, the agent must not invent filler. Byline fallback is the OpenVibe team until an author is mapped to a profile. No external search, image generation, publication or paid tool is introduced; existing stored shots and the typographic hero are sufficient for this stage. Blog persists the workflow/run/model provenance, attaches figures, and enforces human review.

This branch builds on AI choices PR #397. The writer lives in `server/workflows/devblog.js`; its engine integration is a separate step handler, keeping the concurrent choices executor work apart. Tests use a local HTTP provider with canned JSON and local databases only.
